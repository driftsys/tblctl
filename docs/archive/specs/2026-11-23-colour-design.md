# Design: detect meaningful cell colour (#8)

## Intent

Some legacy XLSX attachments carry meaning in cell colour, for example a red,
amber or green status cell. tblctl ignores colour today, so these tables become
T1 (Markdown) or T2 (CSV), and the meaning is lost without a warning. Issue #1
requires "colour not meaningful" for T1 and T2. A table with meaningful colour
must be classified T3 (keep XLSX) with the reason `colour`.

## Goals

- XLSX (and XLSM) tables with meaningful colour on data cells are T3 with the
  reason `colour`.
- Decorative colour does not change the classification.

## Non-goals

- Colour detection for XLS, XLSB, ODS and DOCX. The README lists these as
  unsupported.
- Detecting charts and shapes as images (stays a documented limit, see #9).
- Writing colour to any output.

## Anti-goal

A table whose meaning depends on colour must not be converted to Markdown or
CSV. A false T3 only keeps a table as XLSX, so the rule prefers false T3 to a
missed case.

## Approaches

- **A. Any variation.** Two or more different colours on data cells means T3.
  Simple, but striped rows also become T3.
- **B. Variation that is not decoration.** Ignore the header, whole-column
  colour and alternating row bands. Any other variation counts, and so does any
  conditional-formatting rule on data cells. **Chosen by the user.** After the
  final review on 2026-11-23 the user chose to count row parity only from 4 data
  rows, and to treat any colour in a 1-data-row table as meaningful, because the
  parity rule missed status tables of 1 to 3 rows.
- **C. REVIEW state instead of T3.** Depends on #10, whose REVIEW trigger is not
  decided.

## Design

**Header and data cells.** The first row of the sheet's used range is the
header. This is the same convention the merge rule uses. All later rows in the
used range are data cells, including empty cells inside the range.

**Colour of a cell.** The pair (fill colour, font colour) taken from the cell's
`s` style index in `xl/styles.xml` `cellXfs`:

- Fill colour: the `fgColor` of a `patternFill` whose `patternType` is not
  `none`, as written (`rgb`, `theme` plus `tint`, or `indexed`). Absent or
  `none` means no fill.
- Font colour: the font's `color` element as written. Absent or `auto` means the
  default.
- A cell without an `s` attribute, or with `s="0"`, uses `cellXfs` entry 0.

Colours are compared as written, without resolving themes to RGB.

**Decorative rule.** With 4 or more data rows, colour on data cells is
decorative when the colour of every data cell depends only on its column and on
whether its row number is even or odd. This covers one colour for the whole
table, whole-column colour, alternating row bands, and bands combined with
column colour. Otherwise the colour is meaningful. A highlighted total row is
meaningful under this rule; this is accepted (see Anti-goal). With fewer than 4
data rows, row parity is not evidence of banding, so cells are compared by
column only: two data cells in the same column with different colours are
meaningful. With exactly 1 data row, any data cell whose colour is not (none,
none) is meaningful. A cell with the colour of style 0 counts as (none, none),
because writers give the default font an explicit theme colour.

**Conditional formatting.** Any `conditionalFormatting` element in the sheet XML
whose `sqref` overlaps a data cell makes the colour meaningful.

**Excel table styles** (`xl/tables/*.xml`) do not use cell styles and are
decorative by definition, so they are ignored.

**Where it fits.** A new `Facts.colour: bool`, set in `src/read.rs` for XLSX
sheets by a `quick-xml` reader over `xl/styles.xml` and the sheet XML. The sheet
XML path comes from `xl/workbook.xml` and its relationships. The rule in
`src/rules.rs` adds the T3 reason `colour`, next to `images`. Other formats
leave the fact `false`.

## Tests

- Unit tests for the decorative rule: uniform colour, column colour, row bands,
  bands plus column colour (all decorative); one red cell, a coloured total row
  (meaningful).
- Unit tests for the style reader: fill, font colour, `patternType="none"`,
  missing `s`.
- Integration tests through `classify --json` with XLSX files generated by
  `rust_xlsxwriter`: varied data fills give T3 `colour`; a filled header only
  gives T1; banded rows give T1; a conditional format gives T3 `colour`.
